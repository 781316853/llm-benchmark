## 目标

让未登记（新出现）模型的名称自动合并适配：`claude-opus-5` 与 `Claude Opus 5 (max)` 判定为同一模型，且对未来的任意新模型组合（任意括号 effort 注解写法）自动兼容，无需手工逐条登记别名。

## 根因

`canon()` 的自动归并兜底（autoIndex）只按 `norm()` 键建档/命中：`claude-opus-5` → `claude-opus-5`，`Claude Opus 5 (max)` → `claude-opus-5-max`，两键不同 → 同一新模型被拆成两个 canonical 条目。别名表（data/models.js）只能手工兜住已知模型，新模型只能走这段自动归并，而它恰好未使用已存在的 `normLight()`（剥离 effort 注解）能力。

## 改动（2 个文件，前后端口径必须一致——文件注释已有此约定）

### 1. `js/data.js`（前端，约 57-72 行）
- 新增 `cleanDisplay(raw)` 辅助函数：剥离括号注解 `(...)`（如 `(max)`）、剥离 vibe 降级标记 `[新]`、压缩空白。用于自动建档时的显示名。
- 改造 `canon()` 自动归并兜底段：
  ```js
  var k = norm(raw);
  var fb = autoIndex[k] || autoIndex[normLight(raw)];  // 新增:宽松键命中(兼容 "(max)" 等写法)
  if (fb) return fb;
  fb = { id: cleanDisplay(raw), vendor: "其他", color: ... };
  autoIndex[k] = fb;
  autoIndex[normLight(raw)] = fb;                       // 新增:双键建档,后续任意写法可命中
  return fb;
  ```
- 更新 autoIndex 注释，说明"未登记模型的 effort 注解写法自动归并，无需手工登记别名"。

### 2. `scripts/lib/model-map.js`（抓取端镜像，约 48-64 行）
- 完全相同的 `cleanDisplay` 与 `canon()` 改造（保持与 js/data.js 字节级逻辑一致，文件头注释同步说明）。

## 效果与边界

- 合并任意顺序均可：先出现 `claude-opus-5` 后出现 `Claude Opus 5 (max)`，或反之，均归并为同一条目；`(high)/(Think)/(with fallback)` 等括号注解同理（由剥括号覆盖）。
- 显示名（按用户选择"首现名清洗"）：首次出现的原始名，剥离 `(max)` 等注解与 `[新]` 标记；各榜单表格内仍显示各自原始名（现状不变）。
- 已登记模型零影响：aliasIndex 优先命中，路径不变。
- 明确不改：
  - `normLight` 词表（high|max|medium|xhigh|low|think|preview）——已覆盖快照中全部实际出现的 effort 后缀；不扩词表以免误伤真实变体名（pro/turbo/lite/mini 等）。
  - `data/models.js` 别名表结构。
  - `seen.js` 新上榜徽标（按"榜单|原始名"键追踪，语义不变）。
  - `deepswe.js` 的 `normName`（datalearner 补充去重专用，用途不同）。
  - `deepSwe()/unified()/aaci()/validator` 均以 canonId 为键，自动受益，无需改动。
