# 大模型编码基准整合门户

聚合 **DeepSWE** · **llm2014 Agentic**(原 code_v3) · **Code Arena · WebDev** 三大编码评测、**Agent Arena**(LMArena 真实智能体会话净提升)、**亿模亿样**(前端作品社区盲评 Elo)、**Terminal-Bench(4.0/3.0/2.1)**、**ModelDial 雷达** 与 **Vibe Code v1.1**(Vals AI 从零构建 Web 应用的编码 Agent 实测;VCB-1-100 独立页保留展示),并设「权威基准测试」页收纳 **DeepSWE / Terminal-Bench-Science 0.1 / OSWorld 2.0 / Agents' Last Exam / ARC-AGI-3 / BenchCAD / APEX-1 / HLE / NL2Repo-Bench / ProgramBench / Code Migration / CursorBench / FrontierCode** 等权威基准,聚焦跨基准模型对比。榜单数据统一按**渠道优先级**合并:基准官方实测榜 > 厂商官方发布(论文/发布页)> 第三方聚合与镜像,低层级仅补缺失模型与字段、不覆盖高层级分数。

## 功能

- **总览矩阵**:同一模型在多项基准中的成绩并排对比(含 亿模亿样 前端作品社区盲评 Elo;以及 Terminal-Bench 4.0/3.0/2.1 合并单列);两级表头分「榜单基准」(DeepSWE / Terminal-Bench,基准官方实测榜口径)与「第三方实测」(ModelDial 第三方独立实测 / Code Arena · WebDev 社区盲测 Elo / Agent Arena 真实智能体会话净提升 / llm2014 私有题库 / 亿模亿样 社区盲评 Elo / AI Coding Daily 第三方实测编码榜 / Vibe Code v1.1 第三方实测编码 Agent 榜)两组;**「第三方实测」各列在数值前标出该模型在该榜的实际名次 #N**(取源站榜单序号;WebDev 源站无序号,按原始条目 Elo 并列计名次),悬浮名次可见榜内上榜条目总数;**仅命中≥4 个榜单的模型参与排名并编号**,命中 3 个及以下的模型不计算综合分、不显示排名序号(序号与梯队列均为「—」),仅展示各榜数据——其中命中 2-3 榜的「参考」模型按各榜成绩与排名模型比对,插入到排名行之间的合理位置(默认仅前30区间内显示);勾选「显示全部」则展开**全部在任一基准组有成绩的模型**——排名30之后的排名行、全部「参考」行,以及命中=1 的「单榜」行(不计算综合分、不参与排名,梯队列与序号列均显示「—」,统一排在末尾并标注「仅单榜」),保证"榜上有数据、总览也能看到";**梯队右侧另有「性价比」列**(综合分 ÷ 每百万 token 综合成本,成本按 1M token 实际编程比例 95% 缓存输入 + 4.5% 未缓存输入 + 0.5% 输出折算,单价优先取 codingplan.fyi 模型 API 标价、排名模型缺价由 models.dev 补齐),仅对参与排名的模型(命中 ≥4 榜)计算,可点击列头排序;排名前 20 的排名行(不含「参考」「仅单榜」)中,性价比指数最高者标「最佳性价比」,标记以排名序为准,切换排序列或「显示全部」时保持不变;模型名与徽标分两行排布,徽标不再挤占名称宽度

### 模型名归一(canonical)约定

各源对同一模型的命名写法差异很大(空格/连字符/大小写/effort 注解/日期构建号),`js/data.js` 用**多候选键**归一,任一命中别名索引即视为同一模型:

1. `norm(raw)`——小写 + 非字母数字折叠为连字符(原样);
2. `stripParen` 去括号注解——日期/构建号(如 `(0731)`、`(2026-03-05)`)保留,其余(`(max)`/`(xhigh)`/`(codex-harness)`)剥离;
3. `stripTailEffort` 剥离**结尾**的 effort 标记(`high`/`max`/`xhigh`/`medium`/`thinking` 等),仅在尾部且前方有分隔符时生效;
4. 上述组合(去括号后再去尾部 effort)。

⚠️ **不要用全局子串替换剥离 effort**:早期实现 `/(high|max|medium|xhigh|low|think)/gi` 会把属于模型名的 `Max` 一起吃掉(`Qwen3.8-Max-0902` → 只识别成 `Qwen3.8-0902`),并把 `minimax-m3-thinking` 削成 `minimax-m3-ing`,导致同一模型在矩阵里被拆成两条、NL2Repo 的成绩落不到正确模型上。新增数据源时若发现某模型出现「—」而榜单上明明有分,优先检查该源模型名的写法是否被 `stripTailEffort` 正确归一。

日期构建号(`(20250929)`、`-0915`)、免费路由后缀(`:free`)、厂商别名前缀(`Doubao-`、`nvidia/`)与 `seed2.1` 这类首段粘连写法不会被上述规则自动折叠,需在 `data/models.js` 显式登记别名;2026-10-19 体检按此把 Seed 2.1 Pro、Claude Sonnet/Haiku 4.5、MiniMax M2.1、Tencent Hy3 Preview、Qwen3-Coder 480B、Space Bunny、Nemotron 3 Ultra、DeepSeek 1017 等 10 条「其他」幽灵行归位。2026-10-24 接入 Vibe Code v1.1 时又补登记 Laguna M.1 / XS.2、Ember 1、Mercury 2.5 / 3、Grok 4.1 Fast / Grok 4 Fast、Qwen3-Max、Qwen3.8-Max Internal、Ling-3.0-Flash、Mistral Small 2603 与 Beam 1.0 别名,消除本榜带入的 7 条「其他」多榜幽灵行。排查时先看总览「显示全部」中 vendor=其他 且命中 ≥2 榜的行——多榜幽灵通常就是别名漏配。

## 前端加载策略(首屏只留必要资源)

首屏(默认打开的「总览」页)与后续标签页按需分工,避免低频页面的体积进入关键路径:

- **首屏脚本清单**(`index.html` 的 `defer` 列表)只含总览及各榜单页真正读取的数据:`models` / `deepswe`(+`deepswe_v10`)/ `llm2014` / `arena_webdev` / `arena_agent`(Agent Arena 净提升,计入综合分与命中数)/ `arenaofbias` / `tbench`(+`tbench_v3` / `tbench_v2`,三版合并为一个基准组计入总览)/ `modeldial` / `aicodingdaily`(第三方实测编码榜,计入综合分与命中数)/ `vals_vibe_code`(Vibe Code v1.1,以 OpenHands harness 为主,计入综合分与命中数)/ `vals_vcb`(VCB-1-100,仅独立标签页展示,不计分)/ `hle`(只在权威页列表展示,但分数被总览矩阵「仅参考」列引用)/ `seen` / `news`。
- **按需注入**:仅权威基准页使用的 12 个仅展示榜(`tbscience` / `osworld` / `lastexam` / `automationbench` / `arcagi3` / `benchcad` / `apex` / `nl2repo` / `programbench` / `vals_codemigration` / `cursorbench` / `frontiercode`)与套餐对比页的 `codingplan`,由 `js/app.js` 的 `DATA_SRC` + `ensureData()` 在首次需要时注入(权威页仍在首屏后空闲时预取并预构建);`data/changelog.js`(约 3MB)同理,见 `renderChangelog()`。注:`D.src` 因此改为取值器而非解析期快照(`js/data.js`),否则按需源永远是 `undefined`。
- **ECharts 按需加载**:图表库约 1MB 且默认页一张图都没有,故不进首屏脚本清单 —— 它是 `defer` 脚本,会让 `DOMContentLoaded`(进而 `init`)等它下载完。改由 `js/charts.js` 自己注入:首屏渲染后空闲时预热(`CH.warmup`),或首次真正要画图时即时加载,加载期间的 `CH.apply` 请求排队、就绪后回放(所在页不可见时留到可见再画,见 `CH.flush`)。主源 npmmirror、失败回退 jsDelivr(与 `index.html` 的 `preconnect` 一致)。

实测(同机同数据,`jsDelivr` 首屏等 CDN):首屏渲染 2826ms → 281ms、首屏传输 503KB → 154KB;Fast 3G + 4× CPU 节流下 5293ms → 2321ms。
